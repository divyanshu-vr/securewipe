# Story 3.3: Resilient Wizard Interface with TUI Fallback

## Status
Draft

## Story
**As a** non-technical user performing complete device wiping,  
**I want** a simple interface that works even if graphics fail,  
**so that** I can complete the operation regardless of hardware issues.

## Acceptance Criteria
1. GUI wizard interface tested early in live environment
2. TUI fallback using nwipe's ncurses interface for constrained environments
3. Automatic fallback to text mode if GUI fails to render
4. Same confirmation flow and safety checks in both GUI and TUI modes
5. Clear navigation and progress indicators in both interfaces
6. Plain-language explanations and device identification
7. Emergency stop functionality available throughout process

### Component Specifications
**Wizard Interface Structure** [Source: architecture/source-tree.md#bootable-wizard]:
```
bootable-iso/src/wizard/
├── main_wizard.py       # Step-by-step wizard
├── hardware_detect.py   # Storage device detection
├── confirmation.py      # Multi-step confirmations
└── progress_display.py  # Wipe progress visualization

bootable-iso/src/tui/
├── ncurses_ui.py        # Terminal-based interface
└── menu_system.py       # Navigation menus
```

**Interface Fallback Logic**:
1. **Boot Detection**: Check for graphics capability during boot
2. **GUI Attempt**: Try to start GUI wizard interface
3. **Fallback Trigger**: Detect GUI failure or user preference
4. **TUI Mode**: Switch to nwipe ncurses interface
5. **Consistent Flow**: Maintain same confirmation and safety checks
