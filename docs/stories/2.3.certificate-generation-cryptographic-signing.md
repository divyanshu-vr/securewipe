# Story 2.3: Certificate Generation and Cryptographic Signing

## Status
Ready for Review

## Story
**As a** user who needs proof of data deletion,  
**I want** a cryptographically signed certificate documenting what was deleted,  
**so that** I have verifiable evidence for compliance or peace of mind.

## Acceptance Criteria
1. JSON certificate generated using shared schema from Epic 1
2. Certificate includes device ID, timestamp, complete file list, and deletion method used
3. Cryptographic signature created using pyca/cryptography with local self-signed keys
4. Certificate saved to user-specified location with clear filename convention
5. QR code generated linking to certificate file for easy sharing/verification
6. Certificate includes human-readable summary of deletion operation
7. Before/after disk space comparison included in certificate
8. Certificate generation completes within 30 seconds of deletion completion

### Previous Story Insights

### Data Models
**Certificate Schema** [Source: architecture/source-tree.md#shared-schema]:
- JSON Schema v1.0.0 in shared/schema/certificate_v1.json
- Certificate data structures in shared/models/certificate.py
- Required fields: deviceId, timestamp, files, signature, operationType

**Certificate Structure**:
```json
{
  "schemaVersion": "1.0.0",
  "certificateId": "uuid4",
  "timestamp": "ISO 8601",
  "deviceInfo": {"deviceId": "...", "hostname": "..."},
  "operationType": "quick_clean",
  "deletionSummary": {"totalFiles": 0, "successCount": 0},
  "fileOperations": [...],
  "cryptographicProof": {"algorithm": "...", "signature": "..."}
}
```

### API Specifications
**Cryptography Integration** [Source: architecture/source-tree.md#shared-crypto]:
- Certificate signing via shared/crypto/certificate_signer.py
- Primary: pyca/cryptography RSA implementation
- Fallback: minisign Ed25519 implementation
- Key management via shared/crypto/key_management.py

**Schema Validation** [Source: architecture/source-tree.md#shared-schema]:
- Validation using shared/schema/validator.py
- Schema compliance checking before certificate generation
- Version compatibility via shared/schema/migration.py

### Technical Constraints
**Cryptography Requirements** [Source: architecture/tech-stack.md#cryptography]:
```python
# Primary implementation with fallback
try:
    from shared.crypto.pyca_impl import CertificateSigner
    signer = CertificateSigner()
except ImportError:
    from shared.crypto.minisign_impl import CertificateSigner
    signer = CertificateSigner()
```

**Certificate Schema Compliance** [Source: architecture/coding-standards.md#certificate-schema]:
- All certificate generation MUST validate against shared/schema/certificate_v1.json
- Use shared.schema.validator.validate_certificate() before saving
- Never modify certificate structure without schema version bump
